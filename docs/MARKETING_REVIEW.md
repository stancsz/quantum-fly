# Quantum Fly public launch and README marketing review

Reviewed: 2026-09-12

## Diagnosis

**Audience:** research engineers, quantitative-ML researchers, and open-science contributors who want to test unusual architectures under causal controls.

**Promise:** make a strange structural hypothesis easy to run, falsify, and compare against simpler alternatives.

**Provable difference:** Quantum Fly uses the published male fruit fly connectome as a sparse structural prior, then requires it to compete with classical, no-graph, multi-seed, chronological, and cost-aware controls. The current repository demonstrates a bounded implementation and receipt chain. It does not demonstrate investment value, quantum advantage, biological fidelity, or production readiness.

**Primary action:** run the data-free synthetic demo, then fork one component and share a reproducible positive, negative, or inconclusive result.

**Current friction:** the official-data path requires roughly 1.1 GB of external inputs and a first-run FRED download. The README now separates the 30-second synthetic activation path from official-data reproduction.

## Launch experiments

No external posts are published by this plan. Each channel should receive native value, not identical promotional copy.

| Channel | Audience | Proof unit and angle | CTA | Window and decision rule |
|---|---|---|---|---|
| GitHub profile and repository search | Open-source research builders | Connectome prior challenged by explicit controls | Run the demo; star to bookmark | Review qualified issues, clones, and demo feedback after 14 days; revise wording if visitors repeatedly misunderstand scope |
| Hacker News Show HN | Systems and research engineers | A falsifiable architecture experiment with negative results welcome | Inspect the receipt and challenge one control | Post only with a stable public URL; keep if discussion is technical, stop cross-posting if feedback is mainly category confusion |
| Relevant Reddit communities | Computational neuroscience and quant research readers | Explain contact counts versus learned weights and why no-graph controls matter | Reproduce or critique the method | Follow each community's rules; no repeated generic post |
| PennyLane or quantum-ML community | Quantum software experimenters | Same four-value boundary compared with a classical coordinator | Replace the scorer and report a matched result | Treat replies and reproducible forks as stronger than impressions |

## Measurement plan

Record the repository creation time and initial zero baseline. GitHub traffic is a rolling 14-day window, so snapshot it on a schedule if the project is actively promoted.

- Exposure: post impressions where available, reported per channel.
- Visits: repository views and unique visitors from GitHub traffic.
- Interest: stars and watchers, never labeled users.
- Activation: explicit reports that `python -m scripts.demo` completed, or reproducible issue receipts.
- Adoption: repeat contributors, external forks containing experiments, or cited downstream use.
- Guardrails: misleading investment claims, low-quality issues, support burden, and broken activation commands.

At low traffic, do not claim causal lift or use noisy conversion percentages. Report raw counts and source windows. Keep a README change when it improves successful first use or reduces repeated confusion; revise it when evidence shows qualified visitors cannot identify the scope or run the demo; call the result inconclusive when attribution is missing.

## Unsupported claims and stop conditions

Do not market the historical research gate as profitability, alpha, a trading signal, or forward validation. Do not call simulated quantum output an advantage. Do not call 4,096 selected segments full-brain execution. Do not infer active use from stars, clones, or README polish. Pause promotion if the quick path breaks, data attribution becomes unclear, or contributor intake exceeds the maintainer's ability to respond responsibly.
